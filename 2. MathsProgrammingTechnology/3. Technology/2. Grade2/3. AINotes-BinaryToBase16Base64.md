# Simple Guide: Converting Binary to Base 16 and Base 64

Understanding number bases does not need to be complicated. Every base is just a different way of counting using a specific number of symbols:

- **Base 2 (Binary):** Uses $2$ digits ($0$ and $1$).
    
- **Base 10 (Decimal):** Uses $10$ digits ($0$ through $9$).
    
- **Base 16 (Hexadecimal):** Uses $16$ symbols ($0\text{--}9$ and $A\text{--}F$).
    
- **Base 64:** Uses $64$ printable characters ($A\text{--}Z$, $a\text{--}z$, $0\text{--}9$, $+$, $/$) to turn raw data into plain text.
    

## Part 1: Binary to Decimal (Base 2 $\rightarrow$ Base 10)

In binary, each position represents a power of $2$, starting from $2^0 = 1$ on the far right.

### The Power-of-Two Chart (for 8 bits):

|Position|$2^7$|$2^6$|$2^5$|$2^4$|$2^3$|$2^2$|$2^1$|$2^0$|
|---|---|---|---|---|---|---|---|---|
|**Value**|**128**|**64**|**32**|**16**|**8**|**4**|**2**|**1**|

### How to Convert:

1. Write down the power-of-two value under each bit.
    
2. Add up only the values where the bit is `1`. Ignore the `0`s.
    

### Example:

Convert `11010110` to decimal:

$$\begin{aligned} 1 \times 128 &= 128 \\ 1 \times 64 &= 64 \\ 0 \times 32 &= 0 \\ 1 \times 16 &= 16 \\ 0 \times 8 &= 0 \\ 1 \times 4 &= 4 \\ 1 \times 2 &= 2 \\ 0 \times 1 &= 0 \\ \hline \textbf{Total} &= 128 + 64 + 16 + 4 + 2 = \mathbf{214_{10}} \end{aligned}$$

## Part 2: Decimal to Base 16 and Base 64

Once you have a decimal number, you convert it to another base using **repeated division**.

- Divide the number by the target base ($16$ or $64$).
    
- Record the **remainder**.
    
- Take the integer quotient and divide again, until the quotient reaches $0$.
    
- Read the remainders **from bottom to top** (last remainder to first remainder).
    

### Step 2A: Decimal to Base 16 (Hexadecimal)

Hexadecimal uses digits $0\text{--}9$, followed by $A=10$, $B=11$, $C=12$, $D=13$, $E=14$, and $F=15$.

#### Example: Convert $214_{10}$ to Base 16

1. Divide $214$ by $16$:
    
    $$214 \div 16 = 13 \quad \text{Remainder: } 6$$
2. Divide $13$ by $16$:
    
    $$13 \div 16 = 0 \quad \text{Remainder: } 13 \quad (\text{Hex: } \mathbf{D})$$

Read remainders from bottom to top: **`D6`**.

$$214_{10} = \mathbf{D6}_{16}$$

### Step 2B: Decimal to Base 64

Base 64 maps numbers $0$ through $63$ to safe text characters:

- Values $0\text{--}25 \rightarrow \mathbf{A\text{--}Z}$
    
- Values $26\text{--}51 \rightarrow \mathbf{a\text{--}z}$
    
- Values $52\text{--}61 \rightarrow \mathbf{0\text{--}9}$
    
- Value $62 \rightarrow \mathbf{+}$
    
- Value $63 \rightarrow \mathbf{/}$
    

#### Example: Convert $214_{10}$ to Base 64

1. Divide $214$ by $64$:
    
    $$214 \div 64 = 3 \quad \text{Remainder: } 22 \quad (\text{Alphabet index } 22 = \mathbf{W})$$
2. Divide $3$ by $64$:
    
    $$3 \div 64 = 0 \quad \text{Remainder: } 3 \quad (\text{Alphabet index } 3 = \mathbf{D})$$

Read remainders from bottom to top: $[3, 22] \rightarrow \mathbf{DW}$.

$$214_{10} = \mathbf{DW}_{64}$$

### Why the Decimal Step Is Impractical for Computers

While decimal is natural for humans, doing binary $\rightarrow$ decimal $\rightarrow$ base 16/64 is inefficient for computers for two big reasons:

1. **Leading zeros are erased:** A binary byte of all zeros (`00000000`) has a decimal value of $0$. If a message begins with a zero byte, turning it into decimal deletes that byte completely.
    
2. **Too much heavy math:** For long binary strings (like an image or file), converting the whole thing into one giant decimal number requires doing division on numbers millions of digits long.
    

Instead, computers use the **direct shortcut**.

## Part 3: Direct Conversion (The Fast Shortcut)

Because $16$ and $64$ are powers of $2$, you don't need any division. You can simply cut the binary string into small chunks.

$$2^4 = 16 \implies \mathbf{4\text{ bits = 1 Hex digit}}$$$$2^6 = 64 \implies \mathbf{6\text{ bits = 1 Base 64 character}}$$

### 3A: Direct Binary to Base 16 (Group into 4 Bits)

To convert any binary string to Base 16:

1. Split the binary string into groups of **4 bits** starting from the right. (Add extra zeros on the left if the last group has fewer than 4 bits).
    
2. Convert each 4-bit group directly into its hex symbol:
    

|4-Bit Chunk|Decimal|Hex Symbol|4-Bit Chunk|Decimal|Hex Symbol|
|---|---|---|---|---|---|
|`0000`|0|**0**|`1000`|8|**8**|
|`0001`|1|**1**|`1001`|9|**9**|
|`0010`|2|**2**|`1010`|10|**A**|
|`0011`|3|**3**|`1011`|11|**B**|
|`0100`|4|**4**|`1100`|12|**C**|
|`0101`|5|**5**|`1101`|13|**D**|
|`0110`|6|**6**|`1110`|14|**E**|
|`0111`|7|**7**|`1111`|15|**F**|

#### Example:

Convert `11010110`:

1. Split into 4-bit groups:
    
    $$\mathbf{1101} \quad \mathbf{0110}$$
2. Look up each chunk:
    
    - `1101` $= 8 + 4 + 1 = 13 \rightarrow \mathbf{D}$
        
    - `0110` $= 4 + 2 = 6 \rightarrow \mathbf{6}$
        

Result: **`D6`** (identical to the decimal method, but completed in seconds).

### 3B: Direct Binary to Base 64 (Group into 6 Bits)

To convert directly to Base 64:

1. Read the binary string in groups of **6 bits** from left to right.
    
2. Calculate the decimal value of those 6 bits ($0$ to $63$).
    
3. Look up the character in the Base 64 table.
    

#### Why 3 Bytes = 4 Base 64 Characters:

Computers store data in bytes ($8$ bits).

- 1 byte ($8$ bits) cannot be divided evenly by $6$.
    
- 3 bytes ($24$ bits) divides evenly into four 6-bit chunks ($24 \div 6 = 4$).
    

So Base 64 always takes **3 bytes of input** and turns them into **4 text characters**.

#### Example:

Convert the 3-byte binary sequence for `"Cat"` (`01000011 01100001 01110100`):

1. Line up the full $24$ bits:
    
    $$010000110110000101110100$$
2. Slice into chunks of $6$ bits:
    
    $$\underbrace{010000}_{\text{Chunk 1}} \quad \underbrace{110110}_{\text{Chunk 2}} \quad \underbrace{000101}_{\text{Chunk 3}} \quad \underbrace{110100}_{\text{Chunk 4}}$$
3. Find the decimal value and character for each chunk:
    
    - `010000` $= 16 \rightarrow \mathbf{Q}$
        
    - `110110` $= 32 + 16 + 4 + 2 = 54 \rightarrow \mathbf{2}$
        
    - `000101` $= 4 + 1 = 5 \rightarrow \mathbf{F}$
        
    - `110100` $= 32 + 16 + 4 = 52 \rightarrow \mathbf{0}$
        

Result: **`Q2F0`**

## Part 4: Necessary Details — What About Padding?

What happens if your data does not divide cleanly into 3-byte ($24$-bit) groups? At the end of a message, you might have $1$ or $2$ bytes left over.

Base 64 uses **padding** with the `=` symbol so the receiver knows exactly how many real bytes were sent:

### Case 1: 1 Byte Left Over (8 bits)

- You take the first $6$ bits to make character #1.
    
- You only have $2$ bits left. Add **four zeros to the right** to make a full 6-bit chunk for character #2.
    
- Since two entire characters are missing to complete the 4-character block, fill the remaining two spots with **`==`**.
    
- Example: 1 byte `'M'` (`01001101`) $\rightarrow$ **`TQ==`**
    

### Case 2: 2 Bytes Left Over (16 bits)

- You take the first $6$ bits for character #1.
    
- You take the next $6$ bits for character #2.
    
- You only have $4$ bits left. Add **two zeros to the right** to make character #3.
    
- Since one character is missing to complete the 4-character block, fill the final spot with **`=`**.
    
- Example: 2 bytes `'Ma'` (`01001101 01100001`) $\rightarrow$ **`TWE=`**
