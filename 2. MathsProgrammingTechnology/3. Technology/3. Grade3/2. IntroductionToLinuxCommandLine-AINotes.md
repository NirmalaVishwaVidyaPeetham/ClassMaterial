## Part 0: The Lore of File Paths & Names (Where Are We, Bestie?)

Before you start typing random commands and breaking things, you gotta understand how computers map out files. Everything on a computer is stored in a tree-like folder structure.

### 1. Absolute Paths (The Full GPS Coordinate)

An **absolute path** is the full address starting all the way from the root directory (the mother of all folders, represented by a forward slash `/`). No matter where you are currently chillin' in your terminal, an absolute path always points to the exact same place.

* **Example:** `/home/username/documents/school/math.txt`

### 2. Relative Paths (Directions from Where You Are)

A **relative path** is like giving directions starting *right where you currently stand*. It changes depending on your current location (`pwd`).

* **Example:** If you are already inside `/home/username/documents`, you can just type `cd school` instead of typing out the whole absolute path.

* **Special Shortcuts:**
  
  * `.` (one dot) means "the current directory you are in."
  
  * `..` (two dots) means "the parent directory" (go up one level).

### 3. File Names & Extensions

File names can have spaces (though pros usually use underscores `_` or hyphens `-` so the terminal doesn't throw a fit). The extension at the end (like `.txt`, `.py`, `.png`) is just a hint to tell you what's inside, though Linux actually cares more about file headers than extensions. Also, **hidden files** start with a dot (`.`), which is why `ls -a` is your best friend.

## Part 1: The Absolute Vibe Check (Basic Navigation & Files)

When you open your terminal, you’re sitting inside a folder (directory). You gotta know where you are and what's around you.

### 1. `ls` (List Files)

This command literally just shows you what files and folders are chillin' in your current spot.

* **How it works:** Just type `ls` and press enter.

* **The Main Options (The Game Changers):**
  
  * `ls -l`: Stands for "long format." Gives you the deep lore—who owns the file, how big it is, and when it was last touched.
  
  * `ls -a`: Stands for "all." Shows hidden files (files starting with a dot, like `.gitignore` or `.config`) that usually ghost you.
  
  * `ls -la`: Combines both. Absolute must-use.

**Example:**

```
ls -la


```

*Vibe check passed: You can now see every single file, hidden or not, with all their stats.*

### 2. `cd` (Change Directory)

Use this when you want to teleport into a different folder using absolute or relative paths.

* **How it works:** `cd [folder_name]` or `cd [absolute_path]`

* **Pro-Tips:**
  
  * `cd ..` takes you back up one level.
  
  * `cd ~` instantly teleports you back to your home folder, no matter how lost you are.

**Example:**

```
cd documents/school


```

## Part 2: The Manual & Text Editing

### 3. `man` (Manual / Help)

If you forget what a command does or what flags it takes, don't guess—consult the ancient texts.

* **How it works:** Type `man [command_name]` to read the official instruction manual for that command. Use the arrow keys to scroll, and press `q` to rage-quit back to your terminal.

**Example:**

```
man ls


```

### 4. `vim` (The Text Editor Boss Fight)

`vim` is a legendary terminal text editor. Warning: it's notoriously confusing to exit if you don't know the password (so pay attention).

* **How it works:** Type `vim filename.txt` to open or create a file.

* **The Survival Guide:**
  
  * When you first open it, you can't type anything. You're in **Normal Mode**. Press `i` to enter **Insert Mode** (so you can actually type text).
  
  * Done typing? Press `Esc` to go back to Normal Mode.
  
  * To save and quit: Type `:wq` (Write and Quit) and hit Enter.
  
  * To quit without saving (if you messed up royally): Type `:q!` and hit Enter.

**Example:**

```
vim notes.txt
# Press 'i', type "Math homework is pain", press 'Esc', type ':wq'


```

## Part 3: Data Sorting, Reading, Destruction, & Bash Magic

### 5. `echo` (Spewing Text Out)

`echo` literally just repeats whatever text you hand it right back onto the terminal screen. It’s super useful for printing messages or sending text into files.

* **How it works:** `echo "your message here"`

* **The Pro-Move (Redirection):** You can use `>` to send that text into a brand-new file, or `>>` to paste it at the bottom of an existing file without deleting what's already there.

**Example:**

```
echo "Sub to my channel" > message.txt
echo "Also smash that like button" >> message.txt


```

### 6. `cat` (Read and Combine Files)

Short for concatenate, `cat` is your go-to when you want to look at the contents of a text file right inside your terminal without opening a heavy editor like `vim`.

* **How it works:** `cat filename.txt`

* **The Main Options:**
  
  * `cat -n`: Numbers every single line as it prints them out. Big brain move for code debugging.
  
  * You can also glue files together: `cat file1.txt file2.txt > combo.txt` drops both files into one.

**Example:**

```
cat -n message.txt


```

### 7. `pwd` & `mkdir` (Where Am I & Make Room)

* **`pwd` (Print Working Directory):** If you're completely lost in your folder maze, type `pwd` and it will spit out your exact GPS coordinates on the computer (like `/home/user/documents`).

* **`mkdir` (Make Directory):** Creates a brand new folder out of thin air. Type `mkdir cool_stuff` and boom, new folder unlocked.

### 8. `cp` & `mv` (Copy, Move, & Rename)

* **`cp` (Copy):** Copies a file to a new location. `cp old.txt new_copy.txt`

* **`mv` (Move / Rename):** Moves a file somewhere else, or if you rename it in the same folder, it acts as a rename tool (`mv old_name.txt new_name.txt`).

### 9. `rm` & `rmdir` (The Trash Compactor / Danger Zone)

Be careful with these, because unlike your desktop recycling bin, Linux doesn't automatically have an "Are you sure?" safety net unless you tell it to.

* **`rm` (Remove / Delete Files):** Deletes a file permanently.
  
  * *Example:* `rm spam.txt`
  
  * *The Danger Flag:* `rm -rf` stands for "recursive and force." It deletes entire folders and everything inside them instantly without asking questions. **Do not run `rm -rf /` or you will wipe your entire computer.** Seriously, low-key career suicide.

* **`rmdir` (Remove Directory):** Deletes an **empty** folder. If there's even a single hidden file inside, it will refuse to delete it, which acts as a nice built-in safety check.
  
  * *Example:* `rmdir old_empty_folder`

### 10. `sort` (Ordering Your Chaos)

Got a messy list of items in a text file? `sort` will alphabetize or numericalize that stuff instantly.

* **How it works:** `sort filename.txt`

* **The Main Options:**
  
  * `sort -r`: Reverses the order (Z to A, or highest to lowest).
  
  * `sort -n`: Sorts numerically instead of alphabetically (so 10 doesn't come right after 1).

**Example:**

```
sort -r scores.txt


```

### 11. What is Bash?

Bash stands for **Bourne Again SHell**. It’s basically the default language/interpreter running inside your terminal that translates your typed commands into actions the computer actually understands. When people say "Bash scripting," they mean writing a mini-program of commands to automate boring tasks.

### 12. `ssh` (Secure Shell - Remote Control)

Want to connect to a remote computer or server over the internet? You use `ssh`.

* **How it works:** `ssh username@ip_address_or_domain`

* **Example:**
  
  ```
  ssh root@192.168.1.50
  ```

It'll ask for a password, and boom—you're typing commands on a computer that could literally be on the other side of the planet.

## Part 4: How to Run This Stuff on Windows Shell

Okay, so Windows historically used `cmd.exe` or PowerShell, which have different syntaxes (like using `dir` instead of `ls`). But you can totally run real Linux/Bash commands on Windows using a few methods:

### Method A: WSL (Windows Subsystem for Linux) — *The God Tier Way*

WSL lets you run a literal, actual Linux environment inside Windows.

1. Open PowerShell **as Administrator**.

2. Run this command:

```

   wsl --install

```

3. Restart your PC when prompted, set up a username/password, and open the "Ubuntu" or "WSL" app. You now have a 100% genuine Linux terminal on your Windows PC. All commands work natively!

### Method B: Git Bash — *The Quick & Easy Way*

If you have Git installed on Windows, it comes with **Git Bash**, a handy app that brings a Linux-like Bash terminal right to Windows.

1. Search for **Git Bash** in your Windows start menu and open it.

2. You can immediately run `ls`, `cat`, `echo`, `sort`, `ssh`, and basic Bash commands right there without installing WSL.

### Method C: Translating to Windows PowerShell (If you're stuck in default PowerShell)

If you're just using standard Windows PowerShell and can't use Linux commands, here is how the syntax translates:

| Action             | Linux / Bash    | Windows PowerShell Equivalent          |
| ------------------ | --------------- | -------------------------------------- |
| List files         | `ls`            | `Get-ChildItem` (or `ls` / `dir`)      |
| Show file contents | `cat`           | `Get-Content` (or `type`)              |
| Print text         | `echo`          | `Write-Output` (or just type the text) |
| Where am I         | `pwd`           | `Get-Location`                         |
| Make folder        | `mkdir`         | `mkdir` or `New-Item`                  |
| Change directory   | `cd`            | `cd` (works the same)                  |
| Manual             | `man`           | `Get-Help`                             |
| Text Editor        | `vim` or `nano` | `notepad filename.txt`                 |
| Sort lines         | `sort`          | \`Get-Content file.txt                 |
| Remove file        | `rm`            | `Remove-Item`                          |
| Remove folder      | `rmdir`         | `Remove-Item` (with `-Recurse`)        |

## Part 5: Homework Exercises (Safe Sandbox Training Arc)

Alright, time to lock in. To make sure you don't accidentally nuke your operating system or delete your homework folder, we are going to do all your training inside a **safe sandbox folder**.

Open your terminal and follow these steps step-by-step:

### Step 1: Build the Sandbox

Let's create a quarantined zone so you can experiment without fear.

```

# 1. Teleport to your home directory

cd ~

# 2. Make a safe playground folder and jump inside it

mkdir safe_sandbox
cd safe_sandbox

# 3. Verify your GPS coordinates (should end in /safe_sandbox)

pwd

```

### Step 2: Spawning Files & Using Echo/Vim

Let's populate our sandbox with data.

```

# Create a text file using echo

echo "banana" > fruits.txt
echo "apple" >> fruits.txt
echo "cherry" >> fruits.txt

# Create another file using vim (Press 'i', type something, press 'Esc', type ':wq' to exit)

vim secret_notes.txt

```

### Step 3: Navigating & Checking Stats

```

# List everything including hidden files

ls -la

# Read your fruits file with line numbers

cat -n fruits.txt

```

### Step 4: Copying, Moving, and Sorting Chaos

```

# Copy fruits.txt to a backup file

cp fruits.txt fruits_backup.txt

# Sort the fruits alphabetically

sort fruits.txt

# Create a subfolder and move the backup file into it

mkdir backup_folder
mv fruits_backup.txt backup_folder/

```

### Step 5: The Cleanup & Destruction Test (Using rm safely)

Let's practice cleaning up our mess safely inside the sandbox.

```

# Delete a single file

rm fruits.txt

# Try to remove backup_folder using rmdir (Warning: This should fail because it's not empty!)

rmdir backup_folder

# Force clean the subfolder using rm

rm -r backup_folder

# Check your work—everything in the sandbox should be gone except what you want to leave behind!

ls -la

```

*Pro-Tip:* Once you are totally done, if you ever want to delete the whole sandbox and escape, just type `cd ~` to step outside, and then safely run `rm -rf safe_sandbox`. GG, you completed the tutorial!
