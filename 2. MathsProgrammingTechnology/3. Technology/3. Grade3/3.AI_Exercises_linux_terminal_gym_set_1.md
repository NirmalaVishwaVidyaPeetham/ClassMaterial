## 🛠️ New Gear Unlocked (Read Before Starting!)

To beat these harder levels, you need to combine what you already know (`ls`, `cd`, `cat`, `echo`, `sort`, `rm`, `cp`, `mv`, `mkdir`) with these god-tier tools:

1. **The Pipe (`|`) — Command Combo Multiplier**
   * **What it does:** Takes the output of the command on the left and feeds it directly as the input to the command on the right.
   * **Example:** `cat names.txt | sort` (Reads the file and immediately sends the text into `sort`).

2. **`&&` — The Chain Link**
   * **What it does:** Lets you run multiple commands on a single line, one after another. The second command only runs if the first one succeeds!
   * **Example:** `mkdir test && cd test` (Makes a folder and immediately teleports into it).

3. **`grep` — The Sniper Search**
   * **What it does:** Searches inside files for a specific word or pattern and only prints the lines that match.
   * **Main Flags:** `-i` (ignores uppercase/lowercase), `-v` (inverts the match—shows everything *except* the word), `-n` (shows line numbers).
   * **Example:** `grep -i "error" server.log`

4. **`wc` — Word Count (The Stat Tracker)**
   * **What it does:** Counts lines, words, and characters in a file.
   * **Main Flag:** `wc -l` only counts the **number of lines** (super useful when combined with pipes!).
   * **Example:** `cat todo.txt | wc -l`

5. **`head` & `tail` — Top and Bottom Peeking**
   * **What it does:** `head` shows the first 10 lines of a file; `tail` shows the last 10 lines.
   * **Main Flag:** `-n [number]` lets you pick exactly how many lines to see.
   * **Example:** `head -n 3 scores.txt` (Shows the top 3 lines).

6. **`uniq` — The Duplicate Destroyer**
   * **What it does:** Removes duplicate lines, **but only if they are right next to each other**. That's why pros always run `sort` first, then pipe it into `uniq`!
   * **Main Flag:** `uniq -c` counts how many times each item appeared.
   * **Example:** `sort items.txt | uniq`

7. **`touch` — Instant File Spawner**
   * **What it does:** Creates an empty file (or multiple files at once) instantly without opening an editor or echoing text.
   * **Example:** `touch index.html style.css app.js`

8. **`find` — The Bloodhound**
   * **What it does:** Searches through your folder tree to locate files by name or type.
   * **How it works:** `find [where_to_look] -name "[pattern]"`
   * **Example:** `find . -name "*.txt"` (Finds all `.txt` files in the current directory and any subfolders).

9. **`chmod` — Permission Control**
   * **What it does:** Changes who is allowed to read, write, or execute (run) a file.
   * **Main Flag:** `chmod +x script.sh` gives a script "execute" powers so you can run it like a program!

10. **Wildcards (`*`) & Brace Expansion (`{}`)**
    * **`*` (Asterisk):** Matches *anything*. `*.txt` means "every file ending in `.txt`".
    * **`{a,b,c}` (Braces):** Spawns multiple combinations at once. `mkdir -p project/{src,bin,doc}` creates all three folders inside `project` instantly! (Note: `mkdir -p` creates parent folders automatically if they don't exist yet).

## Part 1: Speedrunning Folders, Paths, & File Spawning

### Exercise 1: The Instant Project Architect
* **Scenario:** You're starting a new coding project and don't want to type `mkdir` five separate times like a noob.
* **Challenge:** Using a **single command** (with `mkdir -p` and brace expansion `{}`), create a main folder called `cyber_app` that contains three subfolders inside it: `frontend`, `backend`, and `database`.

### Exercise 2: Mass File Spawning & Chaining
* **Scenario:** You need to jump into your new `frontend` folder and spawn three blank code files all in one breath.
* **Challenge:** Use `&&` to teleport into `cyber_app/frontend` and use `touch` to create `index.html`, `styles.css`, and `main.js` on a single command line. Then return to `~/safe_sandbox`.

### Exercise 3: Relative Path Parkour
* **Scenario:** You are sitting inside `cyber_app/frontend`, and you need to copy `main.js` directly into `cyber_app/backend` without leaving your current spot or typing out the full `/home/...` absolute path.
* **Challenge:** First `cd` into `cyber_app/frontend`. From there, use `cp` and the parent directory shortcut (`..`) to copy `main.js` into the `backend` folder and rename the copy to `server.js` at the same time. (When finished, `cd ~/safe_sandbox`).

### Exercise 4: Hidden Configs & Reverse Size Sorting
* **Scenario:** Hidden files and normal files are mixed together, and you want to see which files are taking up the most space, starting with the smallest at the top and largest at the bottom.
* **Challenge:** Check `man ls` (or guess from these flags: `-a` for all, `-l` for long, `-S` for sort by size, `-r` for reverse). Write a `ls` command that lists **all** files (including hidden ones) in **long format**, sorted by **file size in reverse order**.

## Part 2: Data Pipelines, Sorting, & Filtering (`|`, `sort`, `uniq`, `wc`)

### Exercise 5: Building a Messy Server Log
* **Scenario:** Before we can filter data, we need a messy file with duplicate entries.
* **Challenge:** Use `echo` and redirection (`>` and `>>`) to create a file named `loot_drops.txt` containing these exact 6 lines in order:
  `sword`
  `shield`
  `potion`
  `sword`
  `potion`
  `sword`

### Exercise 6: The Duplicate Purge Pipeline
* **Scenario:** Your `loot_drops.txt` has repeat items. If you just run `uniq loot_drops.txt`, it fails because the duplicates aren't next to each other!
* **Challenge:** Use a pipe (`|`) to sort `loot_drops.txt` alphabetically, remove all duplicates using `uniq`, and redirect (`>`) the clean list into a new file called `unique_loot.txt`.

### Exercise 7: Counting Unique Items
* **Scenario:** You want to know how many *unique* items exist in `loot_drops.txt` without even creating a separate file or counting them with your fingers.
* **Challenge:** Chain `sort`, `uniq`, and `wc -l` together using two pipes (`|`) to print just the number of unique items in `loot_drops.txt`.

### Exercise 8: The Leaderboard Top 3 (`sort -nr` & `head`)
* **Scenario:** You have a list of player scores:
  Run this first to generate the file:
  ```bash
  printf "450 Alice\n1200 Bob\n85 Charlie\n990 Dave\n3100 Eve\n" > scores.txt
  ```
* **Challenge:** If you sort `scores.txt` normally, `1200` comes before `3100` because `1` comes before `3` alphabetically! Use `sort` with the numeric (`-n`) and reverse (`-r`) flags, pipe it into `head`, and display **only the top 3 highest scores**.

## Part 3: Sniper Searching & Detective Work (`grep`, `find`, `cat`)

### Exercise 9: Sniper Search in Logs (`grep`)
* **Scenario:** A server is crashing and you need to find every error message in the system log, regardless of whether it's spelled `ERROR`, `error`, or `Error`.

  ```bash
  printf "INFO: System booted\nerror: Disk full\nWARN: High CPU\nERROR: Network down\nInfo: User logged in\n" > system.log
  ```
* **Challenge:** Use `grep` to find all lines containing the word "error" (case-insensitive) inside `system.log`, and include the **line number** where each error occurred.

### Exercise 10: Filtering Out the Noise (`grep -v`)
* **Scenario:** You want to read `system.log`, but you are tired of seeing normal `INFO` messages cluttering your screen.
* **Challenge:** Use `grep` with both the case-insensitive flag and the invert-match flag (`-v`) to print every line in `system.log` **except** the ones containing `"info"`.

### Exercise 11: Combining Logs & Counting Crashes
* **Scenario:** You want to merge `loot_drops.txt` and `system.log` into one mega-file, and also count how many lines have the word `"sword"` in `loot_drops.txt`.
* **Challenge:** 
  1. Use `cat` to combine `loot_drops.txt` and `system.log` into `mega_archive.txt`.
  2. Pipe `grep "sword" loot_drops.txt` into `wc -l` to get the exact count of swords.

### Exercise 12: Hunting Lost Files (`find`)
* **Scenario:** You created a bunch of `.js` (JavaScript) files earlier inside `cyber_app`, and now you can't remember which subfolders they are hiding in.
* **Challenge:** From `~/safe_sandbox`, use the `find` command to search the current directory (`.`) and all its subfolders for any file ending in `.js`.

## Part 4: Wildcards, Permissions, Bash Scripting, & Cleanups

### Exercise 13: Wildcard Mass Relocation (`mv` + `*`)
* **Scenario:** Your `~/safe_sandbox` is getting cluttered with `.txt` files (`loot_drops.txt`, `unique_loot.txt`, `scores.txt`, `mega_archive.txt`).
* **Challenge:** Create a folder called `text_vault` and move **every single `.txt` file** in your current directory into `text_vault/` using a single `mv` command with a wildcard (`*`).

### Exercise 14: Peeking at the End of a File (`tail`)
* **Scenario:** You added a new entry to the very bottom of `text_vault/mega_archive.txt`, and you only want to verify the very last 2 lines of the file without printing the whole thing.
* **Challenge:** Use `tail` to display only the last **2 lines** of `text_vault/mega_archive.txt`.

### Exercise 15: Crafting & Arming a Bash Script (`chmod +x`)
* **Scenario:** Typing commands manually is for mortals. You want to create an executable Bash script that prints your current directory and lists all files automatically.
* **Challenge:**
  1. Use `echo` to write `#!/bin/bash` into `status.sh`.
  2. Append (`>>`) `pwd && ls -la` to `status.sh`.
  3. Give `status.sh` execute permissions using `chmod`, and then run it using `./status.sh`.

### Exercise 16: Remote Recon via SSH (One-Liner Execution)
* **Scenario:** Did you know you can run a command on a remote server via `ssh` without even staying logged in? You just put the command in quotes at the end of the `ssh` line!
* **Challenge:** Write the `ssh` command to connect as user `admin` to `10.0.0.99` and immediately check the disk space usage or current directory (`pwd` and `ls -la`) in one go. *(Note: Since `10.0.0.99` isn't a real server on your network, just write out the command or test your syntax!)*

### Exercise 17: Surgical Strike vs. Nuclear Wipe (`rmdir` vs `rm -r`)
* **Scenario:** Inside `cyber_app`, the `database` subfolder is completely empty, while `frontend` has files inside it.
* **Challenge:** 
  1. Delete `cyber_app/database` using the **safe** directory removal command that *only* works on empty folders.
  2. Delete `cyber_app/frontend` (and all files inside it) using the recursive `rm` command (without using `-f` force, or using `-rf` carefully).
