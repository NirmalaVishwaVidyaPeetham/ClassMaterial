## ⚡ New God-Tier Gear Unlocked

Before starting Set 2, add these heavyweight tools to your mental inventory:

1. **`cut` — The Laser Scalpel**
   
   * **What it does:** Slices specific columns out of text or CSV files based on a separator (delimiter).
   * **Flags:** `-d` sets the delimiter (like `','` or `':'`), and `-f` picks the field/column number.
   * **Example:** `cut -d ',' -f 2 players.csv` (Grabs only the 2nd column from a comma-separated file).

2. **`sed` — The Stream Editor (Auto-Find & Replace)**
   
   * **What it does:** Edits text on the fly inside a pipeline or directly inside a file without ever opening `vim`.
   * **How it works:** `sed 's/old_word/new_word/g' filename.txt` (Prints the file with `old_word` replaced by `new_word` globally). Add `-i` (`sed -i ...`) to edit and save the file directly in-place!

3. **`tr` — The Character Translator**
   
   * **What it does:** Swaps or deletes specific characters from piped input (super clutch for converting lowercase to UPPERCASE).
   * **Example:** `cat shout.txt | tr 'a-z' 'A-Z'` (Turns all lowercase letters into uppercase).

4. **`tar` — The Archive Vault**
   
   * **What it does:** Bundles multiple files/folders into a single `.tar.gz` compressed archive (like a `.zip` file for Linux pros) or unpacks them.
   * **Flags to memorize:**
     * `-c` (create), `-x` (extract), `-z` (compress with gzip), `-v` (verbose/show progress), `-f` (filename).
     * **Create:** `tar -czvf archive.tar.gz folder_name/`
     * **Extract:** `tar -xzvf archive.tar.gz`

5. **`ln -s` — Symbolic Links (Portals / Shortcuts)**
   
   * **What it does:** Creates a "symlink" (a shortcut pointer) to another file or folder. If you edit the shortcut, it edits the original file!
   * **Example:** `ln -s /long/annoying/path/config.txt my_shortcut.txt`

6. **`tee` — The T-Splitter Pipe**
   
   * **What it does:** Normally, `>` sends output to a file so you don't see it on screen. `tee` splits the output in two directions at once: it **prints it to your screen** AND **saves it to a file**!
   * **Example:** `ls -la | tee directory_snapshot.txt`

7. **`$(...)` — Command Substitution**
   
   * **What it does:** Runs a command inside the parentheses first and plugs its result straight into another command or string.
   * **Example:** `echo "Today I am working inside $(pwd)"`

8. **`diff` — The Spot-the-Difference Scanner**
   
   * **What it does:** Compares two text files line-by-line and shows you exactly what changed between them.
   * **Example:** `diff -u old_code.py new_code.py`

9. **`du -sh` — Disk Usage Inspector**
   
   * **What it does:** Shows how much hard drive space a folder or file is actually eating up in human-readable format (`-h` gives KB/MB/GB, `-s` gives a total summary).
   * **Example:** `du -sh ~/safe_sandbox_2`

10. **Standard Error Redirection (`2>` and `/dev/null`)**
    
    * **What it does:** When a command fails, it spits out error messages on channel `2` (Standard Error). If you want to mute annoying error messages, redirect them into `/dev/null` (the Linux black hole where data disappears forever).
    * **Example:** `find / -name "secret.txt" 2> /dev/null`

## Part 1: Slicing & Transforming Data (`cut`, `tr`, `sed`)

### Exercise 1: Column Surgery (`cut`)

* **Scenario:** You have a comma-separated table (`users.csv`) and your boss only wants a clean list of the usernames (Column 2) and their roles (Column 3).
* **Challenge:** Use `cut` with a comma delimiter (`-d ','`) to extract **only fields 2 and 3** (`-f 2,3`) from `users.csv`.

### Exercise 2: Extracting & Sorting Admin Levels

* **Scenario:** You want to find all users in `users.csv` who have the `admin` role, grab **only their usernames**, and sort those usernames alphabetically.
* **Challenge:** Pipe `grep "admin" users.csv` into `cut` to grab only the 2nd column (username), and pipe that into `sort`.

### Exercise 3: ALL CAPS HYPE (`tr`)

* **Scenario:** You want to print the contents of `users.csv`, but transform every single lowercase letter into UPPERCASE, and replace every comma `,` with a tab or space (` `).
* **Challenge:** Pipe `cat users.csv` into `tr` to convert `'a-z'` to `'A-Z'`, and pipe that into another `tr` command to turn `','` into `' '` (a space).

### Exercise 4: Live Stream Redaction (`sed`)

* **Scenario:** Before showing `users.csv` on a livestream, you need to hide the word `admin` by replacing it with `REDACTED` on your screen (without changing the actual file yet).
* **Challenge:** Use `sed` to substitute `admin` with `REDACTED` across `users.csv` and print the output to the terminal.

### Exercise 5: In-Place Config Patching (`sed -i`)

* **Scenario:** Your server config file (`app.conf`) is currently set to `mode=debug` and `status=offline`. You need to push it to production right now without opening an editor.
* **Challenge:** 
  1. First, make a backup of `app.conf` called `app.conf.bak` using `cp`.
  2. Use `sed -i` to permanently replace `debug` with `production` inside `app.conf`.
  3. Use `sed -i` again to permanently replace `offline` with `online` inside `app.conf`.

### Exercise 6: Auditing Your Config Changes (`diff`)

* **Scenario:** You want to verify the exact lines that changed between your original backup (`app.conf.bak`) and your newly patched `app.conf`.
* **Challenge:** Run `diff -u` comparing `app.conf.bak` and `app.conf` to view a clean unified change log (lines with `-` were removed, lines with `+` were added!).

## Part 2: Portals, T-Splitters, & Black Holes (`ln`, `tee`, `/dev/null`)

### Exercise 7: Creating a Shortcut Portal (`ln -s`)

* **Scenario:** Imagine `app.conf` is buried deep inside a massive folder structure. Let's move it deep into a subfolder and create a quick shortcut to it in our main sandbox.
* **Challenge:**
  1. Create a nested directory path `config/production/v1` using `mkdir -p`.
  2. Move `app.conf` into `config/production/v1/`.
  3. From `~/safe_sandbox_2`, create a **symbolic link** (`ln -s`) named `quick_conf` that points to `config/production/v1/app.conf`.
  4. Run `cat quick_conf` to prove your portal works!

### Exercise 8: Splitting the Stream (`tee`)

* **Scenario:** You want to filter `users.csv` for all `admin` accounts, see the results immediately on your terminal screen, AND save those exact results into `admins_only.csv` at the exact same time.
* **Challenge:** Pipe `grep "admin" users.csv` into `tee` to display the output and write it to `admins_only.csv` simultaneously.

### Exercise 9: Dynamic File Naming (`$(...)`)

* **Scenario:** Real sysadmins name their backup files dynamically using information from the system (like their username via `whoami` or the current folder name).
* **Challenge:** Use command substitution `$(whoami)` inside a `cp` command to copy `users.csv` into a new file named `users_backup_[your_username].csv`.

### Exercise 10: Silencing the Noise (`2> /dev/null`)

* **Scenario:** If you try to `cat` a file that exists (`users.csv`) and a file that *doesn't* exist (`ghost_file.txt`) at the same time, Linux prints the good file AND an ugly error message.
* **Challenge:** Run `cat users.csv ghost_file.txt`, but redirect Standard Error (`2>`) into `/dev/null` so that **only** the valid contents of `users.csv` appear on your screen and the error message vanishes into the black hole.

## Part 3: Archiving, Compression, & Disk Forensics (`tar`, `du`, `find`)

### Exercise 11: Packing the Vault (`tar -czvf`)

* **Scenario:** You want to bundle your entire `config/` directory tree into a single compressed archive file so you can email it or back it up.
* **Challenge:** Use `tar` with the create, gzip, verbose, and file flags (`-czvf`) to pack the `config` folder into an archive named `config_backup.tar.gz`.

### Exercise 12: Extracting the Vault in a Clean Room (`tar -xzvf`)

* **Scenario:** You want to test your backup archive by extracting it inside a brand-new folder called `restore_test`.
* **Challenge:**
  1. Create a folder named `restore_test`.
  2. Use `tar -xzvf config_backup.tar.gz -C restore_test` (the `-C` flag tells `tar` which folder to unpack into!) and verify the files are inside with `find restore_test`.

### Exercise 13: Checking Folder Weight (`du -sh`)

* **Scenario:** Your hard drive is getting full and you want to see the total human-readable size of your current `~/safe_sandbox_2` folder, as well as the size of every item inside it.
* **Challenge:** Run `du -sh .` to see the total size of your sandbox, and then run `du -sh *` to see the individual size of every file and folder in your current directory.

### Exercise 14: Mass File Spawning & Batch Renaming Loop

* **Scenario:** Sometimes you need to generate 5 numbered log files (`log_1.txt` through `log_5.txt`) instantly without typing 5 filenames.
* **Challenge:** Create a subfolder called `logs`, and use brace expansion `{1..5}` with `touch` to create `logs/log_1.txt` through `logs/log_5.txt` in a single command! Verify with `ls logs`.

### Exercise 15: Finding Empty Files (`find -empty`)

* **Scenario:** Those 5 log files you just created in `logs/` are completely empty (0 bytes), whereas `users.csv` has data in it. You want to scan your entire sandbox to locate every single empty file.
* **Challenge:** Use `find . -type f -empty` (`-type f` means only look for files, not folders; `-empty` means 0 bytes) to list all empty files in your sandbox.

## Part 4: Advanced Scripting, Env Variables, & Multi-Stage Boss Pipelines

### Exercise 16: Custom Environment Variables (`export`)

* **Scenario:** Bash lets you store secret keys or values in memory called variables so your scripts and commands can use them.
* **Challenge:**
  1. Create a variable called `PLAYER_NAME` by running `export PLAYER_NAME="MasterChief"`.
  2. Create a variable called `LEVEL` by running `export LEVEL=99`.
  3. Use `echo` to print: `"Player MasterChief has reached level 99!"` by referencing `$PLAYER_NAME` and `$LEVEL`, and redirect (`>`) it into `player_card.txt`.

### Exercise 17: Skipping the Header Line (`tail -n +2`)

* **Scenario:** When processing CSV files like `users.csv`, the very first line is the column header (`id,username,role,level`), which messes up sorting and counting! Pro tip: `tail -n +2` means "start printing from line 2 all the way to the end."
* **Challenge:** Pipe `tail -n +2 users.csv` into `wc -l` to count the exact number of **actual players** in the file (excluding the header row!).

### Exercise 18: The Role Frequency Counter (`cut` + `sort` + `uniq -c`)

* **Scenario:** You want a stat breakdown showing how many times each `role` (`admin`, `mod`, `guest`) appears in `users.csv`, sorted from most common to least common.
* **Challenge:** 
  1. Use `tail -n +2 users.csv` to skip the header.
  2. Pipe into `cut -d ',' -f 3` to grab only the role column.
  3. Pipe into `sort`, then pipe into `uniq -c` (which counts duplicates!), and finally pipe into `sort -nr` to put the highest count at the top!

### Exercise 19: Automated Cleanup Script with Arguments (`$1`)

* **Scenario:** Inside a Bash script, `$1` represents the first word/argument you type after the script's name when you run it.
* **Challenge:**
  1. Create a script called `greeter.sh` using:
     
     ```bash
     printf "#!/bin/bash\necho \"Hello \$1, welcome to $(hostname)!\"\n" > greeter.sh
     ```
  2. Make `greeter.sh` executable with `chmod +x`.
  3. Run `./greeter.sh CyberNinja` so it greets `CyberNinja` dynamically!

### Exercise 20: The Ultimate Data Engineering Boss Pipeline

* **Scenario:** Time for the final test of Set 2. You need to process `users.csv` to build a clean leaderboard of non-guest players.
* **Challenge:** Write a **single pipeline** that:
  1. Skips the header line of `users.csv` (`tail -n +2`).
  2. Filters **out** any line containing `"guest"` (`grep -v`).
  3. Extracts **only** the `username` and `level` columns (`cut -d ',' -f 2,4`).
  4. Replaces the comma `,` with a colon `:` (`tr ',' ':'`).
  5. Transforms all usernames to UPPERCASE (`tr 'a-z' 'A-Z'`).
  6. Uses `tee` to both print the final list to your screen AND save it into `elite_roster.txt`.
